# 旧版 Cloudflare 与手动凭据兼容

Picup 使用 r2connect 管理 OAuth、Cloudflare 请求和凭据生命周期，并使用 `r2connect/keyring` 保存新凭据。应用只保留旧格式的兼容读取与清理，不再写入旧的分块格式。

## 旧版 OAuth 连接

旧文件 `<配置路径>.r2-oauth.json` 继续保留。查询状态、列出连接和开始一次新的浏览器授权只读取公开元数据，不为加载旧账号打开钥匙串。

第一次使用某个旧连接，或用户主动断开该连接时，才处理该连接的旧凭据。每个旧连接独立导入一个 SDK session，文件为 `<配置路径>.r2connect/<原连接ID>.json`；不同的旧授权不会合并，原连接 ID 和 profile 绑定保持不变。旧 Token ID 与尚待清理的历史 Token ID 进入 SDK 状态，后续续期、删除 Token 和撤销授权由 SDK 执行。

迁移先验证旧数据及 SDK 支持格式，向新的系统存储命名空间写入并回读校验凭据，再原子保存 SDK 状态，最后在同目录的 `legacy-import.json` 标记导入。公开状态和迁移记录均不包含 OAuth Token 或 S3 密钥。旧文件及旧凭据在导入阶段保持原样；中途失败保留原资料，已写完状态但最后标记失败时可仅补齐标记，不再次读取旧凭据。

新 SDK session 另有公开路由文件 `<sessionID>.picup.json`，保存 Picup 的公开连接快照，不包含 SDK Token ID 或秘密。SDK 完成远端撤销后，若本地凭据删除暂时失败，应用仍能通过原连接 ID 找到该 session，并显示待清理状态供重试；最后一个连接完成远端及本地清理后，才移除路由与 SDK 状态。单独丢弃一个候选不会移除其他连接的路由。旧连接已有原元数据作为这一路由，不重复保存秘密。

待清理、已删除桶 Token 而尚未撤销 OAuth 的连接，会进入 SDK 的仅清理状态，仍可通过「断开」完成剩余远端步骤。SDK 确认断开成功后，应用再清理对应旧本地凭据并标记完成；清理失败保留状态供重试。已完成远端步骤的旧记录也必须由用户主动「断开」才收尾，不在上传或后台读取时删除资料。

无法等价表达的旧状态会明确提示「先用旧版断开此连接后再迁移」，例如授权被其他连接复用但远端清理尚未完成，或必要旧凭据已丢失。此时不会覆盖旧文件、移除原钥匙串条目或静默丢弃 Token 清理记录。

处理路径是：停止使用该连接，保留当前配置目录和钥匙串条目；退出新版应用后，使用保留的迁移前 Picup 副本，以相同通道和配置路径打开，在存储设置中完成该连接的断开，再回到新版重新连接。需要保持原 OAuth Client ID；不要用另一个应用的身份处理旧授权。若没有迁移前副本或旧版也无法断开，请保留这些资料并反馈迁移受阻信息，不要通过清空文件或凭据来消除提示。桶内图片不属于迁移或断开时的删除范围。

## 手动 S3 / R2 凭据

新保存的系统凭据引用为 `keyring:<32位ID>`，由 SDK 的 SecretStore 保存完整值；具体平台的分块、拒绝访问及原生调用均由 SDK 处理。写入和回读校验成功、配置提交完成后，配置文件才移除原明文密钥。失败保留输入和原配置。

旧版的裸 32 位引用仍可读取，保留 Endpoint 与 Bucket 绑定校验；读取不改写旧条目或配置。主动保存替换凭据时使用新引用，旧代凭据继续保留给可能共享它的其他 profile。

Dev、正式通道及不同规范化配置目录使用各自命名空间。用户拒绝系统凭据访问后停止自动重试；只有主动连接、断开或保存替换凭据，才允许对应存储重新请求访问。测试使用 SDK 的内存接口和本地 HTTP 替身，不读取真实用户配置或钥匙串。
